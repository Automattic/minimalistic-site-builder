# Plan — Pure-PHP block fixer (replace the Node re-serializer)

Replace the production Node block re-serialization step (`bin/block-fixer/`)
with `PhpBlockFixer implements BlockFixer`. The production runtime must need
only PHP 8.1: no Node process, `node_modules`, or Composer install. Development
and CI retain the pinned Node implementation as an oracle until the PHP
implementation has passed the cutover and observation gates.

This is a bounded compatibility implementation for the block set and input
shapes generated by this repository. It is not a general PHP implementation of
Gutenberg.

---

## Why

Every build currently shells out through `src/NodeBlockFixer.php` to
`bin/block-fixer/fix-templates.js`. The locked JSDOM currently requires Node
`^20.19.0`, `^22.13.0`, or `>=24.0.0`, plus the full Gutenberg/JSDOM dependency
graph on the production host. The rest of the build pipeline runs in PHP.

The Node layer does substantially more than call a few block renderers:

- The default parser recovers malformed delimiters, represents freeform
  content, sources attributes from saved HTML, validates blocks, applies
  built-in repairs, and may apply deprecated block migrations.
- `overlayCommentAttributes()` then additively restores the raw comment JSON;
  parsed attributes that were absent from the comment can still survive.
- `createBlock()` sanitizes attributes against the final registered schema,
  whose attributes and order include block-support hooks not present in raw
  `block.json`.
- `serialize()` combines each block's `save()` function, RichText and React
  serialization, block-support filters, style-engine output, comment JSON
  encoding, and top-level whitespace rules.
- The paragraph fixer runs both before parsing and after serialization.

A PHP implementation is still tractable because the runtime input domain is
closed and can be described by a checked-in compatibility manifest. The work is
therefore a frozen Gutenberg compatibility layer, not only a collection of
hand-written `save()` renderers.

## Compatibility decision

### Canonical markup is the JS fixed point

One invocation of the current Node fixer is not idempotent for every existing
theme. In the audited corpus, one file changed again on pass two and stabilized
on pass three. Exact one-pass Node output and strict PHP idempotence therefore
cannot both be requirements.

Let `F` be one invocation of the pinned Node transformation, including the
current CLI rule that leaves the original file untouched when
`fixBlocksInTemplate().changed` is false, and define:

```text
C(input) = repeatedly apply F until the bytes stop changing
```

The oracle runner must stop after at most five passes and fail if it has not
converged. `PhpBlockFixer` must produce `C(input)` in one invocation, and a
second PHP invocation must make no changes:

```text
P(input) === C(input)
P(P(input)) === P(input)
```

This is an intentional correction to the current one-pass behavior, permitted
by the project's green-field compatibility policy. The regression discovered
in `projects/tbilisi25/theme/parts/footer.html` becomes a checked-in fixture.

### Freeze the complete oracle, not one package

The oracle is identified by:

- The SHA-256 of `package-lock.json`.
- Exact `process.version`, platform, and architecture; the supported production
  requirement may remain a Node major, but fixture provenance is exact.
- The immutable container-image digest used by the Node-enabled oracle CI job,
  so routine host/runtime updates cannot silently change fixture provenance.
- Resolved versions of `@wordpress/blocks`, block library, block editor,
  default parser, style engine, RichText/element packages, React, and JSDOM.
- The hash and generator version of the checked-in registered-block snapshot.

`tests/fixtures/block-fixer/oracle-manifest.json` records this fingerprint.
Changing it requires regenerating and reviewing the schema snapshot and golden
fixtures in the same change.

### Supported input domain

In scope:

- Immediate `templates/*.html` and `parts/*.html` files processed by the
  current CLI.
- Core blocks assigned a save strategy in the checked-in support manifest.
- Current-schema comments produced by this pipeline.
- HTML-only attribute repairs, malformed markup, freeform content, unknown
  blocks, and deprecated shapes explicitly covered by golden fixtures.
- Every block and attribute/support branch observed in the committed fixture
  inventory.

Out of scope unless separately added to the manifest:

- Arbitrary third-party blocks.
- Gutenberg's complete historical deprecation catalog.
- Arbitrary browser-compatible HTML parsing outside the selectors and malformed
  cases exercised by the supported snapshot.

An input discovered in a real project that falls outside this domain must first
be reduced to a checked-in failing fixture. It is not acceptable to hide it
behind a pass-through percentage.

## Observable contracts

Markup parity and report compatibility are separate contracts.

### Strict markup contract

1. `BlockFixer::fix(string $themeDir): string` edits eligible files in place.
2. For every supported input, PHP output is byte-equal to the pinned JS fixed
   point, including comments, HTML, entities, attribute/class/style order,
   whitespace, freeform content, and trailing newlines.
3. One PHP invocation runs its in-memory one-pass transformation repeatedly,
   with the same five-pass cap as the oracle, until the bytes stabilize. The
   next public invocation is a no-op.
4. Nested-paragraph repair runs before parsing and after serialization.
5. `core/media-text` infers `mediaType` when `mediaUrl` is present without it.
6. Unknown blocks and freeform nodes follow the pinned parser/missing-block
   behavior. PHP must not invent a warning line that Node does not use as part
   of markup handling.
7. Discovery, domain validation, parsing, transformation, and staging of all
   files finish before commit. Oracle-defined recoverable malformed-input cases
   return their pinned fallback bytes normally. An unsupported input,
   non-convergence, or error before commit throws `RuntimeException` and writes
   no transformed file. Each replacement during commit is atomic. If a later
   replacement fails, earlier files may already contain complete canonical
   bytes; no file may be truncated, and retrying the fixer must converge safely.

Validation, built-in repairs, and deprecation adapters are in scope whenever
they change final bytes, even though Gutenberg's diagnostic machinery is not
ported wholesale.

### Strict production report contract

The returned string keeps a summary as its first line so `FixBlocksStep` can
echo it, followed by human-readable file detail. The summary grammar remains:

```text
[fix-templates] N/M file(s) re-serialized, K issue(s) fixed, D style/class value(s) dropped across T theme(s).
```

The following behavior is contractual:

- Eligible paths are processed in normalized lexical order.
- Files without `<!-- wp:` receive `skip`; they are excluded from `M`.
- Other files receive `FIXED` or `ok` based on original bytes versus canonical
  final bytes.
- `N`, `M`, and `T` have the current CLI meanings.
- Dropped styles and classes are computed from the original input to the
  canonical final output, not from an intermediate Node pass.
- Style declarations are normalized around the first colon; class tokens and
  styles are occurrence-counted; a loss greater than one retains `(xN)`.
- `D` counts emitted dropped-value records, matching the current CLI, rather
  than the sum of occurrences recorded inside `(xN)`.
- `DROPPED style` and `DROPPED class` wording, values, ordering, and file paths
  remain exact because `FixBlocksStep::droppedVerticalRhythmStyles()` consumes
  those lines.
- A missing, non-directory, or unreadable `$themeDir` throws before discovery.
  For a valid call, including an empty theme, `T = 1` because the PHP interface
  accepts one theme directory.

`K` is the count of deterministic PHP compatibility-repair issue entries on
changed files. Countable repair codes are nested-paragraph repair, media-type
inference, custom-class/anchor/ARIA recovery, and named deprecation adapters.
Rows are unique by file, block path, and repair code across internal convergence
iterations; they are emitted only when the file's canonical final bytes differ
from its original bytes. `K` must equal the count of emitted countable rows, but
it is not required to equal Gutenberg's validation-issue count.

### Intentional report non-parity

Exact Gutenberg validation/deprecation message text, console formatting,
stderr capture, issue ordering, and the duplicated summary produced by
`NodeBlockFixer::fix()` are not compatibility requirements. No production
consumer parses them. The differential harness compares a normalized report
DTO containing file status, dropped entries, and `N/M/D/T`; it does not compare
the raw Node and PHP report strings or `K`.

If exact `K` or validation prose becomes a requirement, generic validation and
deprecation support must be estimated as a separate project before changing
this contract.

## Oracle fixtures and coverage

The ignored `projects/` directory is mostly already canonical and is absent in
a clean checkout. It is useful as optional smoke evidence but cannot be a
milestone gate: a pass-through implementation matched 685 of 705 audited files
(97.2%). The former `>=85%` corpus gate is removed.

### Checked-in golden layout

```text
tests/fixtures/block-fixer/
  oracle-manifest.json
  coverage.json
  cases/
    <case-name>/
      input/parts/*.html
      input/templates/*.html
      expected/parts/*.html
      expected/templates/*.html
      report.json                # normalized original-to-fixed-point contract
      repairs.json               # reviewed PHP repair rows and exact K
      case.json                  # milestone, oracle passes, capabilities covered
```

`bin/generate-block-fixer-fixtures.js` runs the pinned oracle to its fixed
point, records the pass count and normalized report, and updates fixtures only
with an explicit `--update` flag. Tests never regenerate expected output.
Generated changes must be reviewed like source changes.

The generator computes the normalized report from the original input and the
fixed-point output. It must not reuse the last convergence pass's stdout,
because that pass necessarily reports no changes. M0 extracts the current JS
dropped-content detector into an importable module used by both the production
Node CLI and the oracle generator, so expected drop records cannot drift through
duplicated logic.

`coverage.json` maps every supported block strategy, renderer branch, source
type, selector form, compatibility repair, support hook, and report branch to
at least one case. CI fails if the supported inventory contains an uncovered
entry or refers to a block absent from the registered snapshot.

Every case declares the first milestone/capability gate at which PHP must pass
it. Later fixtures may be checked in during M0, but M1 and M2 pass sets are
derived mechanically from this field and cannot be reclassified without a
reviewed fixture diff.

`repairs.json` is reviewed compatibility intent rather than Node-generated
validation output. It names the expected PHP repair codes and block paths and
asserts exact `K`; the generator never overwrites it. Cases cover every repair,
an unchanged repair candidate, and `K = 0` on the second PHP invocation.

Required adversarial cases include:

- The known three-pass Node convergence case and a direct PHP second-pass
  assertion.
- HTML-only custom class, root `id`/anchor, and `aria-label` recovery.
- Deprecation migrations exercised by existing generated input.
- Freeform before, between, and after blocks; unknown void and paired blocks.
- Balanced, mismatched, stray, and unclosed delimiters; malformed comment JSON;
  and the oracle's fallback behavior.
- Void/paired comment selection based on rendered content.
- Every generated source type, including `attribute`, `property`, `html`,
  `text`, `rich-text`, `raw`, `children`, `node`, `tag`, and recursive `query`
  where present.
- Descendant/child selectors and boolean attributes.
- RichText entities, literal NBSP, inline formatting, and `<br>` handling.
- Nested blocks and complete `innerContent` interleaving.
- JSON apostrophes, quotes, backslashes, `--`, `<`, `>`, `&`, Unicode, empty
  object versus array, nested key order, wrong types, defaults, negative zero,
  and exponent formatting.
- Color/element/link, typography, spacing, border, shadow, dimensions,
  background, alignment, layout, self-stretch, and child-layout support.
- Navigation with and without `ref`, navigation-link children, social-links
  wrapper output, a true dynamic-null block, raw HTML, and missing-block output.
- No-op, changed, skipped, empty theme, deterministic path order, both HTML
  quote styles, repeated drops with `(xN)`, and vertical-rhythm drops.

Failure preservation is tested separately with fault injection. A throwing
parser/renderer and a failed staging write must raise `RuntimeException` and
leave every theme file unchanged. A simulated failure after one successful
atomic replacement may leave that complete canonical file in place, but every
file must contain either original or canonical bytes and a retry must converge.
These are not represented as supposedly valid oracle inputs and do not
contribute to `K`.

The optional real-project differential must report project and file counts. A
zero-project environment is an explicit `SKIP`, never a pass; M0 adds real skip
support to the test harness.

## Architecture

The runtime goal is Node-free and Composer-free, not literally one source file
or no vendored code. Development tools may use Node. Any vendored WordPress
HTML/style classes and required shims are checked in with license and provenance
notices.

      Selector.php
      RichText.php

### Parser and typed values

Do not extend or reuse `BlockMarkup` for this parser. Its tolerant editing
semantics, malformed-delimiter recovery, and associative JSON representation
are deliberately different and remain useful to other PHP steps.

`DefaultParser` ports the state machine of the pinned
`@wordpress/block-serialization-default-parser`. Its model preserves:

- Gutenberg's mismatched and stray closer behavior.
- Void and paired blocks.
- Ordered top-level freeform nodes.
- `innerHTML`, child blocks, and all `innerContent` chunks/placeholders.
- Original delimiters and raw source slices needed by freeform, missing-block,
  and failure behavior.
- The distinction between JSON objects and arrays.

Comment JSON uses ordered typed values: `{}` must never collapse into `[]`.
Number handling and encoding cannot rely on PHP's default associative-array or
float serialization.

### Registered schema snapshot

`generated-registry.php` is produced by a Node development tool, not by reading
raw `block.json` in PHP. The generator initializes the same JSDOM environment
and registration path as the fixer, then captures the final `getBlockType()`
state after block-support filters run.

The generated data distinguishes three sets:

- **Registered universe** — every block returned by the pinned registry; used
  to detect upstream drift.
- **Supported subset** — registered blocks explicitly admitted by the PHP
  compatibility manifest; this is the coverage and cutover gate.
- **Observed set** — registered names found in committed fixtures and optional
  real-project scans; this must be a subset of the supported set. Unregistered
  names exercise the separate missing-block strategy.

For the registered universe it records:

- Registered attribute order, type, enum, default, role, and source.
- Nested queries and selector details.
- Final supports configuration.
- Save probe results for default and manifest fixture attributes: null output,
  inner-block sentinel output, or rendered elements. Conditional behavior still
  requires an explicit strategy and branch fixtures.
- An instrumented, versioned trace of effective block-support/save-filter order;
  supports metadata alone does not define class and style ordering.
- Oracle package versions and lockfile hash.

CI has a Node-enabled oracle job that regenerates this file and fails on an
unexplained diff. Normal PHP unit and integration tests consume the checked-in
snapshot and do not require Node.

### Attribute sourcing and normalization

`AttributeSourcer` implements every source type and selector construct reachable
from blocks in the supported subset. Registry generation may inventory other
constructs, but adding a block that uses one to the supported manifest fails
until the construct is implemented and covered.

Sourcing needs a lossless HTML fragment tree with source spans, nesting,
`innerHTML`, recursive queries, and the closed CSS selector grammar in the
registry, including descendant and child combinators. A lone
`WP_HTML_Tag_Processor` is not sufficient. M1 must either:

1. Vendor the complete required WordPress HTML tokenizer/API class set and add
   the small tree/selector layer, or
2. Implement a project-owned source-span tokenizer/tree for the closed grammar.

The M1 feasibility gate chooses between them using the sourcing, malformed HTML,
and RichText goldens. `DOMDocument` is not used because its HTML repair and
serialization do not match the oracle.

The per-block normalization order mirrors the observable JS pipeline:

1. Parse raw delimiters and typed comment attributes.
2. Normalize core names, freeform nodes, and missing blocks.
3. Resolve attributes as `getBlockAttributes()` does: source values from saved
   HTML or comment attributes, apply type/enum validity at this stage, and use
   registered defaults for invalid or missing values.
4. Render and run the bounded initial-validity predicate. Only after that
   predicate fails, apply the byte-affecting built-in repairs used by supported
   cases: custom class recovery, HTML `id` to `anchor`, and `aria-label` to
   `ariaLabel`; then validate again.
5. Apply an explicit block-specific deprecation adapter for every migration hit
   by supported fixtures, or eliminate that deprecated shape upstream.
6. Additively overlay original raw comment attributes only while the parsed and
   grammar trees have parallel matching named blocks. Skip freeform entries and
   stop that subtree on a name/shape mismatch, matching
   `overlayCommentAttributes()` rather than guessing.
7. Apply `core/media-text` `mediaType` inference.
8. Recreate the block as `createBlock()` does: filter to registered keys, fill
   missing defaults, perform RichText/string and legacy `node`/`children`
   conversions, and emit registry order. Do not re-run type/enum rejection after
   the raw overlay; JS can retain a wrong-typed authored value at this point.

M0 instrumentation records validation repair and deprecation hits while
fixtures are generated. Cutover is blocked while any observed byte-affecting
behavior lacks an adapter or upstream correction. Exact Gutenberg diagnostic
messages are not generated.

`Validator` is the minimum save-output/token-equivalence implementation needed
to gate the three built-in repairs exactly where Gutenberg does. Every repair
has positive and negative fixtures; applying the repairs unconditionally is not
acceptable.

Deprecation tracing uses a pinned development-only instrumentation hook around
`applyBlockDeprecatedVersions` that records block name, matched deprecation
index, and before/after attributes and inner blocks. The instrumentation patch
hash is part of the oracle manifest.

### Explicit save strategies

Every supported block has an explicit strategy; the absence of a renderer is
never interpreted as dynamic:

- `DYNAMIC_NULL` — verified `save() === null`; comment-only.
- `INNER_BLOCKS` — saved content is serialized inner blocks.
- `STATIC_RENDERER` — a PHP renderer produces saved markup.
- `CONDITIONAL` — save behavior depends on attributes.
- `RAW_CONTENT` — saved content comes from a raw attribute.
- `MISSING_BLOCK` — pinned missing-block/original-content behavior.

Important assignments include:

- `core/navigation`: `CONDITIONAL`; `ref` omits saved inner content, otherwise
  it uses `INNER_BLOCKS`.
- `core/navigation-link`: `INNER_BLOCKS`.
- `core/social-links`: `STATIC_RENDERER` for its `<ul>` wrapper plus children
  and block supports.
- `core/html`: `RAW_CONTENT`.
- Server-rendered blocks: `DYNAMIC_NULL`, but only after verification against
  the registered snapshot.
- Unknown blocks: `MISSING_BLOCK`, without a PHP-only report warning.

The generator inventories every observed and registered block. A test fails if
a supported registered block has no explicit strategy. The generic
`MISSING_BLOCK` strategy is separately exercised by an observed unregistered
name such as `core/figure`.

At runtime, a registered name outside the supported subset, an unsupported
source/selector, an unimplemented renderer/support variant, or an unknown
deprecated signature fails closed during the pre-write phase. It is never
treated as a dynamic block or silently passed through. An unregistered name may
use the separately covered generic `MISSING_BLOCK` path.

### Rendering, RichText, and block supports

Renderers return a small typed save tree rather than concatenating final HTML.
`HtmlSerializer` centralizes React-compatible behavior:

- Text and attribute escaping.
- Boolean and omitted attributes.
- Void elements and raw/RichText fragments.
- Attribute and inline-style order.

`BlockProps` applies support modules in the same effective order as the pinned
`useBlockProps.save()` hook chain. The supported families include alignment,
custom classes, colors and element/link colors, font family/size and typography,
spacing, border/radius, shadow, dimensions/min-height, background images,
layout/self-stretch/flex size, child-layout classes, preset variables, and
skip-serialization rules.

The pinned package already contains a PHP style-engine implementation. It may
be adapted or vendored with its required shims, but the JS fixed-point fixtures
remain authoritative for class and property order.

`Serializer` applies schema-based comment-attribute omission, the JS-compatible
comment encoder, rendered-content-based void/paired selection, inner blocks,
and top-level `"\n\n"` joins.

### JavaScript-compatible comment encoder

Do not reuse `BlockMarkup::serializeComment()`.

`JsJsonEncoder` reproduces the pinned `JSON.stringify()` behavior and
Gutenberg's subsequent replacements:

- Ordered object keys and object/array identity.
- JavaScript object-key enumeration order, including array-index-like keys.
- JavaScript number formatting, including negative zero and exponent forms.
- Backslash, quote, `--`, `<`, `>`, and `&` escaping with matching case.
- Default, sourced, local-role, unknown, and `undefined` attribute omission.
- Registered-schema comment key order.

The JSON cases listed in the fixture matrix are an M1 exit requirement, not
post-cutover cleanup.

M1 documents the number-conversion algorithm and tests exponent thresholds,
IEEE-754 large-integer rounding, shortest-round-trip formatting, and negative
zero. A seeded Node-enabled differential test covers boundary and randomized
finite doubles; committed boundary goldens keep the PHP-only suite reproducible.

### Fixer and report layer

`PhpBlockFixer` owns deterministic file discovery, supported-domain validation,
the five-pass in-memory convergence loop, a two-phase transform/commit flow,
atomic changed-file writes, normalized report records, formatting, and the
summary. One internal pass includes pre-paragraph repair, parse/normalize,
recursive save/serialize, and post-paragraph repair. `DroppedContentDetector`
ports the current occurrence-counting algorithm exactly and compares the
original bytes with the final converged bytes.

`BlockFixers::default()` is introduced during M0. `BLOCK_FIXER=node|php`
selects the implementation; the default remains `node` until every M3 cutover
gate passes.

## Supported block inventory

The inventory is generated from real inputs and the registered snapshot, then
checked in alongside `coverage.json`. The existing volume order remains useful
for scheduling, but it is not a parity percentage or cutover gate.

| Tier | Blocks / behavior |
|------|-------------------|
| Core static | paragraph, group, column, heading, image, separator |
| Structural | columns, buttons, button, spacer, list, list-item |
| Rich | cover, media-text, quote, pullquote |
| Tail | gallery, table, embed, html |
| Special strategies | navigation, navigation-link, social-links, verified dynamic-null blocks, freeform, missing/unknown blocks |

Each renderer lands with fixtures for every conditional branch and support
combination it uses. No declared supported static block may fall back to
pass-through at cutover.

## Milestones

### M0 — Contract, fixed-point oracle, and dirty fixtures (3–5 days)

- Implement a fixed-point oracle wrapper with a five-pass convergence cap.
- Implement the registered-runtime generator and check in its initial snapshot,
  including save probes and effective support/filter order.
- Pin the Node-enabled oracle CI job to an immutable container image digest.
- Record the complete dependency and instrumentation fingerprint.
- Add the pinned validation/deprecation tracing hooks used during fixture
  generation.
- Extract the JS dropped-content detector for shared CLI/oracle use.
- Check in the initial adversarial fixture suite, normalized report DTO,
  reviewed repair expectations, and milestone-tagged coverage manifest.
- Add explicit `SKIP` support to the test harness and make the optional
  `projects/` differential fail or skip clearly when it finds zero projects.
- Introduce `BlockFixers::default()` and `BLOCK_FIXER`, defaulting to Node.
- Make oracle fixture generation explicit and review-only.

Exit criteria:

- The known second-pass regression is reproduced and the oracle converges.
- Original-to-fixed-point report expectations are synthesized independently of
  the final no-op Node pass.
- Full registered, supported, and observed block sets are distinct and checked.
- Fixture tests run from a clean checkout without `projects/`.
- The committed pass set contains changed inputs, so a no-op PHP implementation
  cannot later satisfy it through canonical corpus volume.
- Markup and report contracts above are encoded as tests.

### M1 — Shared compatibility foundation (1–2 weeks)

- Typed block/freeform parser and malformed-delimiter behavior.
- Typed JSON values and `JsJsonEncoder`.
- PHP registry loader and attribute-resolution semantics for the checked-in
  snapshot.
- HTML sourcing feasibility spike and chosen tokenizer/tree/selector approach.
- RichText normalization for the fixture matrix.
- Minimum validation predicate that gates built-in repairs.
- Built-in byte-affecting compatibility repairs and observed deprecation
  adapters.
- Deterministic report model and dropped-content detector.
- At least one complete vertical slice (paragraph plus a nested group/support
  case) through parser, sourcing, validation/repair, overlay, recreation,
  renderer, block props, HTML/comment serialization, and convergence.

Exit criteria:

- 100% byte parity on every M1 fixture.
- 100% normalized report-contract parity on every M1 fixture.
- Exact PHP repair-code rows and `K` match each fixture's reviewed
  `repairs.json`, including second-pass `K = 0`.
- Every source type and selector form reachable from the M1 supported subset is
  implemented; adding a block with an unsupported construct fails manifest
  validation.
- No unhandled observed validation/deprecation hit remains.
- Positive and negative fixtures prove the built-in repairs are gated rather
  than applied unconditionally.
- Seeded number-format differential tests pass against Node.
- The team re-estimates M2 from measured renderer/support complexity. If exact
  HTML/RichText/source parity requires a general browser or JS runtime, stop and
  reconsider the runtime constraint before broad renderer work.

### M2 — Save strategies, supports, and renderers (2–3 weeks)

- Complete the centralized HTML/RichText serializer and ordered block-support
  pipeline beyond the M1 vertical slice.
- Assign every inventory entry an explicit save strategy.
- Implement renderers in corpus-volume order, including conditional navigation,
  social-links, cover, media-text, table, and gallery behavior.
- Add golden and unit fixtures with every renderer/branch; update the coverage
  manifest in the same change.

Exit criteria for each tier and for M2 overall:

- 100% fixed-point byte parity on that tier's committed fixtures.
- 100% normalized report-contract parity.
- Exact repair rows and `K` match the tier's reviewed expectations.
- No pass-through for a declared supported static block.
- No uncovered strategy, source, support hook, or renderer branch.
- PHP is idempotent for all completed fixtures.

### M3 — Integration, soak, and cutover (3–5 days)

- Port `tests/unit/fix_blocks_test.php` and
  `tests/integration/pipeline_test.php` to the factory/PHP implementation.
- Replace direct `NodeBlockFixer::default()` construction in production entry
  points (`bin/build.php`, `bin/create.php`, `bin/eval.php`, and
  `bin/images.php`) with `BlockFixers::default()`.
- Add factory tests for PHP default, Node override, and invalid configuration.
- Run the complete unit and pipeline suites with an unusable `NODE_BIN` and
  without `node_modules` available to the runtime.
- Run the optional differential over a non-empty local project corpus and
  record counts/mismatches as advisory review evidence when that ignored corpus
  is available; do not commit generated proof.
- Exercise real builds with `BLOCK_FIXER=php` before changing the default.

Cutover requires all of the following:

- Every committed fixture is byte-equal to the JS fixed point after one PHP
  pass.
- A second PHP pass changes no file and emits no new drop/repair entry.
- All normalized report, failure-preservation, and vertical-rhythm gates pass.
- The registered inventory and coverage manifest are complete.
- PHP-only unit and full-pipeline tests pass with Node unavailable.
- No production entry point constructs `NodeBlockFixer` directly; direct use is
  confined to the factory's Node override and oracle tooling/tests.

Only then does `BlockFixers::default()` switch from Node to PHP. Documentation
is updated to say that production no longer requires Node.

### M4 — Observation and decommission (later, separate decision)

Keep the Node override, oracle tools, lockfile, and Node-enabled differential CI
through several real PHP-default build cycles. After that observation period,
decide separately whether Node dependencies remain in development artifacts or
move to a dedicated oracle package. They are removed from production artifacts
at cutover.

## Estimate

The previous roughly two-week estimate is removed. A planning range of
**4–7 weeks** is more credible for the closed supported domain, fixed-point file
bytes, and dropped-content/report-contract parity. Re-baseline after the M1
feasibility gate.

Exact Gutenberg validation diagnostics or the full historical deprecation
catalog are excluded from that range and require a separate spike.

---

## Risks and mitigations

- **HTML sourcing and malformed-fragment normalization** — prove the selected
  tokenizer/tree/selector design in M1 before renderer expansion; fail registry
  generation on unsupported selectors.
- **Validation/deprecation changes that affect bytes** — instrument fixture
  generation, require an explicit adapter or upstream correction, and block
  cutover on unhandled hits.
- **JSON and comment encoding** — use typed values and a dedicated JS encoder;
  exhaustive cases are an M1 gate.
- **RichText and React serialization** — centralize escaping and save-tree
  output; test entities, raw spans, boolean attributes, and ordering directly.
- **Block-support/style drift** — fingerprint the whole lockfile, preserve hook
  order in one support pipeline, and regenerate fixtures only in reviewed
  Gutenberg-upgrade changes.
- **False confidence from canonical local themes** — use checked-in dirty
  goldens and coverage completeness as gates; keep `projects/` smoke-only.
- **Silent unsupported-block pass-through** — require an explicit strategy for
  every supported/observed block and prohibit static pass-through at cutover.
- **Vendored WordPress code and shims** — record exact upstream source, version,
  license, local changes, and dependency list.
- **File corruption on failure** — transform and stage everything before commit,
  replace each file atomically, permit only complete original/canonical bytes
  after a mid-commit failure, and prove retry convergence with fault injection.

## Out of scope

- Porting `LayoutFixer`, `FixBlocksStep`, or the vertical-rhythm gate, except for
  factory wiring and tests required by the new fixer.
- `content/*.html` and `patterns/*.php`; the production CLI currently processes
  only immediate `templates/` and `parts/` HTML files.
- Arbitrary third-party blocks or unobserved historical Gutenberg migrations.
- Exact current one-pass Node output; the canonical contract is the pinned Node
  fixed point.
- Exact Gutenberg validation issue counts, prose, console output, or stderr.
- Compatibility shims for stored external data or consumers; this repository is
  green field.
