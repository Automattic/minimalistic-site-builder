# Tree Graph Implementation Plan (x-pipeline brochure port)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the x-pipeline brochure workflow (from `x-companion-x-agent`, worktree `surfaces`) into this repository as a third selectable graph — the model authors JSON block trees, a live WordPress Playground sandbox validates and compiles them through real `wp.blocks`, design tokens land as user-origin global styles, and pages publish to the sandbox.

**Architecture:** New PHP steps under `src/Steps/` composed by `StepComposition::tree()`, supported by ported pure-PHP libraries under `src/TreeGraph/`. A trimmed WordPress companion plugin at `sandbox/companion/` is mounted into a detached Playground boot; a small Node driver at `bin/sandbox/` runs the harness compile and the measured verification in headless Chrome. Files under `projects/<slug>/` remain the only boundary between steps. Only the brochure lane is ported — no custom blocks, no schema packages (S5/S6 and the file-map/block-css gates are deliberately absent).

**Tech Stack:** PHP ≥ 8.1 (no new Composer deps), `@wp-playground/cli` (already vendored), `playwright-core` against system Chrome (same as `bin/screenshot`), Playground blueprint steps.

**Spec:** The x-pipeline source of truth: `/Users/andreidraganescu/Sites/x-companion-x-agent/.claude/worktrees/surfaces/` — `pipeline/stages/s{1,2,3,4,7,8,9}-*.mjs`, `pipeline/lib/*.mjs`, `pipeline/budget.mjs`, `pipeline/prompts/*.md`, `pipeline/schemas/brief.schema.json`, `contract/schemas/design-tokens.schema.json`, `x-companion/includes/class-{validator,theme-tokens,manifest,harness,placeholders,pattern-library,rest}.php`, `x-companion/harness/harness.js`, `x-agent/mcp/src/oracle.ts` (extractLayout / collectImages / eagerLoadImages / classNameMap), `x-agent/templates/theme-json/emitter.ts` (diffAgainstThemeTokens).

## Global Constraints

- Brochure only: `custom_blocks` and `schema_packages` are forced-empty in the brief; no block/schema factory, install, or file-map/block-css gates are ported.
- The 1×1 placeholder GIF from x-companion (`class-placeholders.php::gif_bytes()`) is preserved byte-for-byte, including the sized-PNG variant and palette-slug resolution.
- Minimal code transfer: no MCP toolchain, no app passwords/users/posture walls, no epoch-free shortcuts — publishing goes through new companion `publish/*` routes with a sandbox-only constant gate instead of authenticated core REST.
- Maximal MSB reuse: `Step`/`StepDeclaration`/`StepGraph`/`Pipeline`/`Project`/`Llm`/`Narrator`/`BuildReport`/`config/models.json`; files-on-disk between steps; `--from`/`--until` resumability.
- Indentation: 4 spaces everywhere, including PHP ported from the tab-indented x-companion sources.
- Verification failures (measured gates in the final step) degrade to `warnings.json` + loud narration — MSB's "fix, degrade, warn — never crash" doctrine — except budget breaches and token-gate failures, which throw (there is no deliverable without them).
- XX artifact names are kept inside the project dir: `brief.json`, `instance.json`, `tokens.json`, `tokens-dry-run.json`, `sections/*`, `furniture-slice.json`, `trees/*`, `pages/*.html`, `published.json`, `budget.json`, `verify.json`, `screenshot.png`, `report.md`, plus `sandbox.json` and `logs/tree-ledger.jsonl`.

## Graph shape

`StepComposition::tree()` (seeds: `['meta.json']`), step ids in order:

```
sandbox → brief → read-instance → tokens → section-trees → tree-repair → publish → tree-images → verify
```

| id | class | XX source | LLM |
|---|---|---|---|
| sandbox | SandboxStep | tools/playground/boot.mjs (trimmed) | no |
| brief | TreeBriefStep | s1-brief.mjs | 1 call |
| read-instance | ReadInstanceStep | s2-read-instance.mjs | no |
| tokens | TreeTokensStep | s3-tokens.mjs | 1 call |
| section-trees | SectionTreesStep | s4-sections.mjs | S + 2 calls |
| tree-repair | TreeRepairStep | s7-repair.mjs (trees only) | ≤1 per failed tree |
| publish | TreePublishStep | s8-publish.mjs (minus installs/images) | no |
| tree-images | TreeImagesStep | s8 image pass, via MSB ImageClient | image calls |
| verify | TreeVerifyStep | s9-verify.mjs | no |

Selection: new env `SITE_BUILD_GRAPH` (`tree` \| `html-first` \| `blocks`) owned by `StepComposition::selectedGraph()`; falls back to the legacy `SITE_BUILD_HTML_FIRST` boolean. CLI flag `--tree` (mutually exclusive with `--html-first`/`--blocks-first`) sets it. `meta.json` records `graph: "tree"`; `StepComposition::resumeGraph(?string $recorded, ?string $requested): ?string` generalizes `resumeHtmlFirst` (which stays, delegating). `SiteBuilder::pipeline()` returns the tree pipeline (no fallback wrapper) when selected.

`--with-images` on the tree graph records `tree_images: true` into `meta.json` (build.php, after createProject; also on `--from` resume when passed) and skips the legacy `postImages` phase. `--no-serve`/serve: the tree graph never boots a separate preview — the sandbox is the site; build.php prints its URL and exits without the keep-alive loop.

- `TreeRepairStep` — trees only: for each `status: fail` artifact, one `repair` task call (maxAttempts 1) validated by the same gate chain; then gateTree (validate + ink + compile parity); on failure `substituteInk` rescue → pattern baseline (gated) → minimal slot; records `dead.json`; updates `trees/*` and `artifacts.json`.
- `TreePublishStep` — final epoch = fresh `fingerprint()`; placeholder minting per image-intent node with band-based tone (no-images mode: band bg mixed 12% toward its ink via `mixHex`/`toneOf`; with-images mode: accent role hex) through `POST placeholder` (1×1 GIF); page assembly by concatenating section tree blocks (epoch restamped); validate (empty allow-set) + compile per page (one harness batch for all pages); writes `pages/<slug>.html`, `trees/page--<slug>.json`; publishes via SandboxClient (`publishPage` with `template: 'page-no-title'`, `publishSettings` with front page, `deleteSamplePage`, furniture parts at final epoch — nav links injected flat into the designed header's single `core/navigation`, deterministic nav post + two-paragraph footer floor otherwise), writes `published.json`.
- `TreeImagesStep` — `meta.tree_images` false → narrate "placeholders stay" and return. True: for each published page, walk `trees/page--<slug>.json` for imageIntent nodes; `ImageClient::generateBatch` (prompt = intent + brief art_direction style line + "No text, no watermarks, no typography, no logos."; aspect_ratio nearest supported to the node's aspectRatio); meter each image into the ledger (`task_type: image`); upload via `uploadMedia`; swap `url`/`id` on the exact nodes; recompile the page through the harness; `updatePageContent`; writes `images/images-manifest.json` and updates `pages/<slug>.html`.
- `TreeVerifyStep` — `Harness::verify` on the site root (wait domcontentloaded, retry once on an empty measurement after 3s); screens: pass flag, outline, band widths, band seams, text contrast, images loaded; failures → `warnings.json` under `verify` + loud narration (MSB doctrine — deviation from XX's throw, documented); advisories logged; ONE screenshot via `node bin/screenshot/screenshot.js <url> screenshot.png`; writes `verify.json`; `TreeReport::write`.
